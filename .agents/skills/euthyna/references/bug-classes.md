# 缺陷类别专项要求

> 判定一条结论时，**先定类别，再套对应的默认假设**。
>
> 因为不同类别下，「什么算可疑」和「什么算误报」是**相反的**。用同一套直觉判所有类别，
> 必然在某些类别上系统性出错。

---

## 0. 默认假设按类别翻转

这是本文件最重要的一条，也是最反直觉的一条：

| 类别 | 默认假设的方向 |
|---|---|
| **内存破坏** | 默认**是误报**。在内存安全语言里几乎总是误报，除非有编译器缺陷或类型系统漏洞 |
| **逻辑缺陷** | 默认**不是误报**。「逻辑缺陷会通过每一个边界检查」——**不要让干净的静态分析说服你它是误报** |
| 其余类别 | 逐类见下 |

把这两行搞反，就会在内存破坏上刷出一堆误报，同时在逻辑缺陷上漏掉真漏洞。

---

## 1. 内存破坏

**先做语言核查**：safe Rust、未使用 `unsafe.Pointer`/cgo 的 Go、以及所有托管语言
（Java / C# / Python / JS）里的内存破坏**几乎总是误报**。先过这一关，能省掉绝大部分工作。

过了语言核查再查：

- 具体破坏了什么（栈 / 堆 / 全局 / 对象）
- 破坏的大小与偏移**是否攻击者可控**
- 是有用的原语（任意读、任意写、虚表覆写）还是仅仅崩溃
- 分配器加固是否在位
- UAF 的对象生命周期：释放后是否真能再被引用
- 类型混淆：要给出**类型不匹配的证明**，不是「看起来像」

---

## 2. 逻辑缺陷

**默认假设反过来：不要让「静态分析很干净」说服你这是误报。**

- 对照 **spec / RFC / 设计文档**判，不是只读代码
- 绘制**全部状态转换**——能否到达开发者未预料的状态？
- 找出**从未被强制的隐式假设**
- 认证类缺陷要验证**全部**认证与授权路径，不是主路径

---

## 3. 竞争条件

- 实际竞争窗口是**纳秒还是秒**？两者是完全不同的问题
- 攻击者能否**扩大窗口**（慢速文件系统、大分配、CPU 争用）
- 核验线程模型：单线程 / 事件循环 / 多线程，结论完全不同
- 检查全部同步原语，而不是只看有没有锁
- 文件系统类要看**符号链接竞争**（TOCTOU 的经典形态）

---

## 4. 整数问题

- 每一点的**精确类型与取值范围**，不是「大概是个整数」
- 有符号溢出（C/C++ 里是未定义行为）vs 无符号回绕（**有定义**）——不能混为一谈
- 追踪所有 cast / conversion / promotion
- **结果是否真的用于危险用途**：分配大小、数组下标、循环边界。用于日志打印的溢出不是漏洞
- 开启 `-Wconversion`、`-Wsign-compare` 这类检查，让编译器替你找

---

## 5. 加密弱点

- 对照 NIST / IETF 标准与已知攻击检查参数
- 核验随机源：是不是密码学安全的
- **nonce 重用要证明实践中确实能发生两次**，不是「理论上可能」
- 时序侧信道要看两点：攻击者能否触达，以及网络抖动是否让远程攻击不切实际
- 与参考实现的测试向量对比

---

## 6. 注入

- 追攻击者输入从入口到 sink 的**完整路径**，沿途是否净化、转义
- 框架的自动转义是否启用，**且未被绕过**
- XSS 要看上下文：HTML 正文 / 属性 / JS / URL，**各需不同的转义**，一种转义不能覆盖全部
- 路径穿越要看：访问检查**之前**是否已经规范化
- 用**真实 payload** 走完所有中间处理，不要在手写的示例里验证

---

## 7. 信息泄露

- **具体泄露什么**：栈泄露（能拿 ASLR 基址或 canary）是严重的；静态字符串毫无价值
- 泄露的数据对进一步利用**是否真的有用**
- 未初始化内存要**证明读点确实未初始化**
- 时序侧信道看测量精度与噪声水平
- 错误信息**是否真能到达攻击者**——写进日志不算

---

## 8. 拒绝服务

- 资源消耗比与放大倍数**是否有意义**
- 资源可回收还是永久耗尽——两者严重性差别很大
- **复杂度主张要证明实际最坏输入能触发**，不要只声称 O(n²)。
  要指出具体输入、给出实测耗时
- 崩溃是否**可靠**触发
- 服务是否自动重启：100 毫秒重启和需要人工介入是两个完全不同的问题

---

## 9. 反序列化

- 攻击者**是否确实控制**到达反序列化点的数据
- classpath / import 图里**有没有可用的 gadget 链**——
  **没有 gadget 链，不安全反序列化只是设计异味，不是可利用缺陷**
- 库与版本，以及该版本已知的链
- 类型限制 / allowlist 过滤器是否在位
- 语言特定形态：Java `ObjectInputStream`、Python `pickle`、PHP `unserialize`、.NET `BinaryFormatter`

---

## 用法

1. 在阶段 C 的**第零步**就给断言定类别
2. 类别决定默认假设的方向（见 §0）
3. 走数据流与可利用性分析时，**叠加**该类别的专项检查（上表）
4. 门禁评估时，该类别特有的「什么算阻止」也按上面的定义判

> 类别定错，后面全错。**不确定时明说不确定，不要挑一个像的凑。**
