# 事实契约（判定层消费指南）

> 这是一份**消费指南**，不是设计文档。它回答：拿到一条事实之后，判定层能从中推出什么、不能推出什么。
>
> 完整契约见仓库的 `docs/fact-contract-zh.md`。

---

## 一条事实长什么样

```jsonc
{
  "id": "fact-007",
  "kind": "history",                 // 事实类别
  "statement": "本次变更删除了 4 行来自提交 ab877f9d70 的代码……",
  "status": "established",           // established | refuted | unknown
  "evidence": { "file": "src/a.js", "line": 104, "commit": "ab877f9d70" },
  "method": "command",
  "command": "git blame --porcelain -L 104,104 <rev> -- src/a.js",
  "confidence": "exact",             // exact | approximate
  "detail": { }                      // 类别特有的结构化载荷
}
```

---

## 三条消费规则

### 规则 1：`unknown` 不是「干净」

三态是硬约定：

| status | 判定层能做什么 |
|---|---|
| `established` | 可以据此下结论 |
| `refuted` | 可以据此下结论（反向） |
| **`unknown`** | **什么都不能推**。它既不是支持也不是反对，是「不知道」 |

把 `unknown` 当成「没问题」，是这套契约唯一会致命的使用错误。

### 规则 2：`approximate` 不得参与门禁

`confidence: approximate` 的事实**明确被排除在门禁判定之外**。

这条不是保守，是来自实践：有工具在「无法确定作用域」时会合成一个近似结果，
并明确标注它**即使在强制模式下也不参与阻断**。本框架沿用同一约定。

门禁只吃 `exact`。

### 规则 3：缺数据先看覆盖表

报告里的 `coverage.notEvaluated` 列了**没测什么、为什么**。

**引用任何「干净」的结论之前，先读这一节。**
`notEvaluated` 非空时，不要把它读成「测过了没问题」。

## 事实里**没有**什么（这是设计，不是遗漏）

| 不存在 | 为什么 |
|---|---|
| 分数（score / 0–100） | 分数不可复算，会变成「拿分数当门禁」 |
| 严重性等级 | 严重性是**判断**，不是事实 |
| 修复建议 | 同上 |
| 「可能」「大概率」 | 模糊词会掩盖缺失 |

**测量的归测量，判断的归判断。** 一条事实如果带着 `severity: high`，
说明产出它的那一层已经替判定层做了决定，而那个决定是不可复算的。

## 各类事实的读法

### `history` —— 被删代码的来源

| 字段 | 读法 |
|---|---|
| `detail.classification` | `security` / `fix` / `none`。**分类器的两种错误代价不对称**：漏掉安全提交比多报更危险，所以它偏向宽 |
| `detail.byFile` | **每个文件各有多少行**。`blamedLines` 是总数，可能跨多个文件——不要以为证据里那个文件包含全部 |
| `detail.commitSubject` | 提交信息原文。**不要只看分类，读一眼信息本身** |
| `command` | 可直接执行的复现命令，含真实行区间 |

**注意**：`history` 只说「这行来自哪个提交、那个提交像不像安全修复」，
**不说**「删掉它就是个漏洞」。后者是判定层的事。

### `reintroduction` —— 被移除又加回

`detail.securityOrigin` 非 `null` 表示：该行的出现次数曾被一个信息里含安全关键词的提交改变过。
配合「该行在 base 版本中不存在」，可推出**它曾被移除、现在被加回**。

**这不等于「这是个回归」**——它等于「这里需要人看一眼」。判定层据此决定要不要拉高优先级。

### `test_coverage` —— 调用计数

⚠️ **这个类别只能证伪，不能证实。**

| 事实 | 能推出 |
|---|---|
| 调用计数 = 0（`status: established`） | ✅ **确实没被调用过**。所有依赖它的行为都没被执行验证 |
| 调用计数 > 0（`status: unknown`） | ❌ **不能**推出「执行过」。进入函数不等于任何特定调用点被执行 |

原因：底层覆盖率数据会把**从未执行的调用点报成已覆盖**（抛出异常后的直线代码就是典型），
所以「已覆盖」这个方向本身不可靠。**产出器里根本没有「已执行」这个输出**，这是刻意的。

推论：**不要**用「计数非零」去关闭一个「这里没测试」的担忧。要证明确实执行过，
只能靠能真正触达该调用点的演示。

### `artifact` —— 产物证据

报告文件、演示运行的退出码与用例数。**门禁 1 与门禁 4 靠它。**

读法：退出码与用例数必须是**真实捕获的输出**，不是预期值。
用例数为 0 的「通过」不是通过。

## 产出器的退出码

配套 CLI 的退出码是对外契约，可直接用于 CI：

| 码 | 含义 | 判定层该怎么反应 |
|---|---|---|
| `0` | 已测量，无安全相关发现 | 正常继续 |
| `10` | 已测量，且存在 `security` 分类的事实 | **提高优先级**，不要直接当结论 |
| `1` | 用法错误 | 修命令 |
| **`2`** | **完全无法测量** | **不得当作干净**。要么换测量方式，要么把相关判据标为不可评估 |

`2` 与 `0` 的区别是这份契约存在意义的缩影：**没能测量，和测了没问题，是两回事。**
