# 第四轮靶场设计（预注册）

> 状态：设计稿。第四轮开跑前，本文档作为「预注册」提交——先写清要测什么、怎么算成功，
> 再跑，避免事后挑选数字。第三轮设计见 `DESIGN-round3.md`。

## 为什么有第四轮

第三轮留下两条已写明的局限（`RESULTS-round3.md` 局限节）：

1. **p6b 的 v3 白名单守卫从未被独立裁定。** 第三轮 run-1 裁定的是 v1 副本
   （分隔符守卫，被裸 `..` 击穿），run-3 裁定的是 v2 副本（resolve 归属检查，
   被 bsdtar 的 `@` 操作数语义击穿）；run-3b 的补裁发现第二处缺陷后，守卫升级为
   v3 裸名白名单。v3 目前只有出题人自己的 exploit（3/3 拒绝）撑着。
2. **跨模型检验缺位。** 第三轮路由目录只有一家，run 3 按预注册 fallback 如实降级为
   单模型三轮。现在路由目录有三个模型（deepseek-v4-flash-ga-260731、
   deepseek-v4-pro-ga-260813、glm-5.3-flash），跨模型点可以真正执行。

## 目标

1. **全量 18 案例 × 3 次独立裁定 = 54 次**，不是只裁 p6b：全量重跑让跨模型点作用于
   整个套件、让每个案例拿到第四个独立样本，也让 p6b v3 按第三轮局限节的措辞
   「重新计入」非漏洞集合。
2. **模型分配（预注册，开跑前定死）**：run 1/2 = `deepseek-v4-flash-ga-260731`
   （与第三轮同仪器，轮间可比）；run 3 = `glm-5.3-flash`（不同模型家族，跨模型
   独立性最大化）。`deepseek-v4-pro-ga-260813` 记录在案但不采用——它与 run 1/2
   同家族，换它测的是「更强」而非「更独立」；留给未来想做强度对照的轮次。
3. **协议 v3 全量沿用**：三条泄漏通道清单化、A/B/C 申报、file-only 报告、禁列结果
   目录、临时目录删掉重建、批前批后清扫。第四轮追加两处修订（v4）：
   - **裁定提取脚本化**（`bench/collect-verdicts.js`）：主控全程不读报告正文，
     只做机器校验（文件存在非空、`VERDICT:` 恰好一行、四块结尾齐全、正文无裁定词）
     与裁定词提取——把第三轮的「主控侧不带结论校验」从手工 grep 变成可复现工具。
   - **模型身份双记录**：报告 CONTEXT DECLARATION 由裁定者自报模型；主控侧在
     派发时显式指定模型参数并记入 verdicts 头注，以派发记录为准。
4. **p6b 头条问题（预注册）**：独立裁定者在只看 claim + src 的条件下，对 v3
   白名单守卫给出什么裁定？两种结局都是有效结果：
   - FALSE POSITIVE（守卫成立）→ p6b 重新计入非漏洞集合；
   - TRUE POSITIVE / INCONCLUSIVE（发现第四种逃逸形状，或证据不足）→ 按第三轮
     先例：主控亲手复现 → 修夹具 → 以 runN-b 补裁 → verdicts 文件注明序列。
   已知且接受的信息面：p6b 夹具源码注释本身记载了两次被绕过的历史（v2 副本在
   第三轮就带着 run-1 的历史注释，本轮 v3 只是把两段历史都写上）。裁定者知道
   「这守卫被加固过两次」不等于知道「v3 是否守得住」——后者正是本轮要测的。

## 成功标准（预注册）

1. **p6b v3**：3 次独立裁定齐备；任何一次非「误报」的裁定，其逃逸形状必须经主控
   亲手复现才采信（第三轮纪律：裁定者抓出题人缺陷，两次都是复现后才修的）。
2. **全量**：真漏洞 24 次运行的召回、非漏洞 30 次运行的特异度、逐案例稳定性；
   任何翻转按「发现」呈现（哪案、第几次、哪个模型）。
3. **跨模型**：run 3 与 run 1/2 的逐案例一致性单独成表；glm-5.3-flash 与
   deepseek-v4-flash 的分歧是本轮最受关注的输出，不是噪声。
4. **污染可控**：全部报告 A/B/C 申报齐备；批清扫台账留档（按第三轮经验，通道③
   ——子会话自摘要——每批都会复发，预期本轮同样需要逐批归档）。
