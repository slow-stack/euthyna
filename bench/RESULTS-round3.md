## run 1 最大的发现：裁定者抓到了靶场自己的 bug

`p6b`（守卫近邻）的 run-1 裁定为实锤，与预注册 ground truth（假）不一致。核查结论：
**裁定者对，夹具错。**

- p6b 第一版守卫只拒绝**含路径分隔符**的名字；而裸 `..` 不含分隔符，穿过守卫后作为
  tar 成员把 `data/` 的父目录整树打进归档——实测 11 个成员全部在 `data/` 之外，
  包括 `src/`、`claim.md`，甚至 `meta.json` 本身。
- 裁定报告的严谨度值得单独记录：唯一逃逸名被精确定位为 `..`，`...`、尾随空格、
  盘符名等近似向量逐一实测排除；claim 文本「未拒绝分隔符」的半句被指出与源码不符
  （源码确实拒绝了），**裁定按机制，不按文本**。
- 修复：守卫改为对成员根做 resolve 后的归属检查（与 p5b 同风格）；
  `exploits.js` 现在同时提交两种逃逸形状（带分隔符的 `..` 段与裸 `..`），
  两种都必须被拒才算守卫生效。修复后 18/18 期望全过。
- 记录口径：run-1 对该案的判定**对当时的副本是正确裁定**，不计为裁定错误；
  修复后的 p6b 从 run 2 进入并补足三次裁定。

这正是靶场要抓的东西：**「守卫存在」不等于「守卫完整」**。第二轮抓过断言与源码不符
（`execSync` vs `execFileSync`），这一轮在提交前抓到了守卫与威胁不符——而且抓它的是
被要求「断言是指控不是证据」的裁定纪律本身。
